2) STOCK vs CUSTOM CONFIG (main difference)
----------------------------------------------------------------------

Stock config (oppo6765_defconfig):
  CONFIG_TOUCHPANEL_OPPO=y
  CONFIG_TOUCHPANEL_NOVA=y
  CONFIG_TOUCHPANEL_NOVA_NT36525B_NOFLASH=y
  # CONFIG_TOUCHSCREEN_NT36xxx_HOSTDL_SPI is not set

Custom config (CPH2185_defconfig):
  # CONFIG_TOUCHPANEL_OPPO is not set
  # CONFIG_TOUCHPANEL_NOVA_NT36525B_NOFLASH is not set
  CONFIG_TOUCHSCREEN_NT36xxx_HOSTDL_SPI=y

Matlab:
  - Stock kernel OPPO ke apne "touchpanel" vendor driver se touch chalata
    hai. Us driver ka source is repo me nahi hai; wo
    "vendor/oppo_touchscreen/oppo_touchscreen/" me hota hai.
  - Custom kernel me is repo ke andar wala NT36525B SPI driver
    (drivers/input/touchscreen/mediatek/NT36525B/) enable kiya gaya hai.
  - Ye driver hardware se baat kar sakta hai, lekin uski ek DT property
    ki requirement hai jo stock DTBO me nahi hai. Isi wajah se probe fail
    ho raha hai.

3) ROOT CAUSE (asli wajah)
----------------------------------------------------------------------

File: drivers/input/touchscreen/mediatek/NT36525B/nt36xxx.c
Function: nvt_parse_dt()

Purana code:

    ret = of_property_read_u32(np, "novatek,swrst-n8-addr",
                               &SWRST_N8_ADDR);
    if (ret) {
        NVT_ERR("error reading novatek,swrst-n8-addr. ret=%d\n", ret);
        return ret;              // <-- YAHI PROBLEM HAI
    }

Matlab:
  - Driver ko DT me "novatek,swrst-n8-addr" chahiye.
  - Stock CPH2185 DTBO me ye property NAHI hai.
  - Property na milne par driver turant error return karta hai.
  - nvt_ts_probe() "err_spi_setup" par chala jata hai.
  - input_register_device() tak baat hi nahi pahunchti.
  - Isliye "touchpanel" input device aur IRQ 19 dono nahi bante.

Ab dekho ki "fix" kyu lag nahi paaya:

  - Aapne source DTS me property add ki:
      arch/arm64/boot/dts/mediatek/oppo6765.dts
      novatek,swrst-n8-addr = <0x03F0FE>;

  - Lekin ye DTS ek OVERLAY hai (/plugin/;), aur ye alag DTBO image
    (oppo6765.dtb / oppo6765_20271.dtb) me jata hai.

  - AnyKernel zip sirf boot image ka KERNEL replace karta hai.
    Wo DTBO partition ko chhoota hi nahi.

  - Isliye phone ke andar wahi purana stock DTBO raha, jisme ye
    property nahi hai. Driver ne property na paakar probe cancel kar diya.

  - Upar se custom "Image.gz-dtb" me sirf generic base DTB gaya:
      CONFIG_BUILD_ARM64_APPENDED_DTB_IMAGE_NAMES="mediatek/mt6765"
    Us DTB ka model "MT6765" hai aur usme touch_ts@0 node bhi nahi hai.
    Asli OPPO touch node stock base DTB + stock DTBO overlay se aata hai.

  - Iska matlab: DTS change sirf tab kaam karta jab aap DTBO (ya poora
    boot + dtbo) flash karte. Sirf AnyKernel zip se nahi.

5) FIX (code patch)
----------------------------------------------------------------------

Patch file: CPH2185-touch-swrstd-fix.patch

Change 1:
  SWRST_N8_ADDR ka default 0x03F0FE kar diya.
  (Stock OPPO DTS me yahi value hai.)

Change 2:
  nvt_parse_dt() me agar property na mile to probe fail na kare.
  Default value use kare aur aage badhe.

Change 3:
  nvt_rest_ddi() me reset_global_gpio invalid ho to skip kar de.
  (Stock DTBO me ye GPIO bhi nahi hai.)

Patch ka main hissa:

    uint32_t SWRST_N8_ADDR = 0x03F0FE;

    ret = of_property_read_u32(np, "novatek,swrst-n8-addr",
                               &SWRST_N8_ADDR);
    if (ret) {
        SWRST_N8_ADDR = 0x03F0FE;
        NVT_LOG("novatek,swrst-n8-addr missing, using default 0x%06X\n",
                SWRST_N8_ADDR);
        ret = 0;
    }

    return 0;

Apply karne ke liye (kernel source folder me):

    cd kernel_oppo_CPH2185
    git apply /path/to/CPH2185-touch-swrstd-fix.patch

Ya manually file edit karo:
    drivers/input/touchscreen/mediatek/NT36525B/nt36xxx.c

        chip is not identified
        parse dt error
        gpio config error
